# 节拍坠落 / Beatfall

手机横屏四轨音游。导入自己的音乐，在浏览器内识别节拍与声音起点并自动编谱；在对应轨道任意高度点击、长按，或按箭头左滑、右滑、上滑。

[在线试玩](https://broken-star1999.github.io/musicgame/) · [GitHub 仓库](https://github.com/broken-star1999/musicgame)

参考用户提供的游戏视频，采用上窄下宽的透视轨道、向判定线靠近的音符、长按光带及击打粒子。保留四轨混合音符，舞台为原创程序绘制的霓虹背景。

## 本地启动

开发/构建使用 Node.js 22（CI）或 24（本次本机验证）。普通玩家只需打开网站，无需安装 Node.js、Python、模型服务或 GPU。

```bash
npm ci
npm run dev
```

打开终端显示的地址，通常为 http://127.0.0.1:5173/。首次进入会自动生成一首约 47 秒的原创演示曲和谱面，无需自行寻找音频。

```bash
npm test          # 核心节奏、谱面与判定测试
npm run test:benchmark # 比较指标、数据观察历史与冻结协议检查
npm run build    # TypeScript 检查和生产构建
npm run preview  # 预览 dist 中的生产版本
```

## 两种识别方式

- **纯算法（默认）**：使用频谱变化检测声音起点，选择连贯节奏来源，跟踪局部拍点，再按主拍、半拍和细分组织四档谱面。不下载或运行模型。
- **模型辅助（可选）**：浏览器在本机运行 Beat This! small0。模型约 9.4 MB、WASM 运行组件约 14.8 MB，首次未压缩资源合计约 24 MB；实际传输受压缩和缓存影响。无需 API Key 或独立模型服务。

在导入区切换即可重做当前歌曲分析。升级到版本 8 首次打开时，旧版识别选择迁移为纯算法，其余设置保留，避免旧默认值继续自动启动模型；此后主动选择模型辅助仍会记住。音频不会上传，模型和运行组件来自网站自己的静态文件。模型资源失败时会显示纯算法谱面提示，可以重新识别或直接游玩。两种路径都可能选错音乐层，建议用自动演示和可选的落点音观察。

模型辅助加载会分别显示模型与运行组件的实际 KB/MB 进度。连接或下载连续 15 秒没有新数据时，自动使用已经完成的纯算法结果；两项资源下载合计最多等待 90 秒。页面主线程还监控模型 Worker，45 秒没有进度便终止它并恢复纯算法谱面，避免模型线程阻塞时一直等待。也可以随时点击“立即用纯算法继续”，直接使用已有分析，不重复处理歌曲。

下载并校验成功后，模型和 WASM 会尽量保存到浏览器的 CacheStorage，下次选歌或刷新时优先复用，并显示“已从本机缓存读取”。缓存命中仍检查文件大小和 SHA-256；损坏时重新下载并覆盖，更新资源后清理同类旧版本。缓存读取最多等待 3 秒、写入与清理最多等待 1.5 秒；存储禁用、配额不足或存储无响应都不会阻止识别。浏览器可能回收缓存，因此不能保证永久保留，也不代表整个网站已经支持离线打开。

手机加载优化包括：原创演示曲在可取消的 Worker 内合成，主线程只接收已完成 PCM；增强分析仅发送一次完整基础数据，之后用增量结果复用频谱、能量和起音数组。菜单预览按最高 30 FPS 绘制，分析、离屏、后台、弹窗遮挡或系统减少动画时停止循环，恢复后继续；游玩继续使用音频时间进行判定。首页采用 Motion 的轻量特性包，保留原有进入动画。桌面节流对照和实际歌曲结果一致性记录见 [手机加载验证](benchmarks/MOBILE_PERFORMANCE.md)，不将模拟结果作为真机结论。

## 使用方法

1. 导入 MP3、WAV、M4A、OGG 或 FLAC 文件。最大 50 MB，时长 2 秒至 5 分钟；具体格式支持由浏览器决定。也可以直接使用内置演示曲。
2. 选择单指、二指、三指或四指，切换后在 Worker 中重新编谱，预览、游戏及结算显示同一档位。四档都使用四条轨道；除长按与滑动占用外，还会规划每根手指的落位、移动时间及交叉关系。生成时可取消，切换指法会终止旧任务。
3. 选择下落方式和速度。默认「透视推进」随轨道变宽平滑加速，使每秒位移与当前轨道宽度的比例保持一致；「屏幕匀速」保持恒定的屏幕纵向像素速度。两种方式都在同一时间到达判定线，速度设置只影响视觉提前量，不改变音乐节奏。
4. 网页默认使用横向布局，选歌、设置、游戏和结算保持同一方向。手机锁定竖屏时整页会自动侧转 90°，无需关闭系统旋转锁；自然横屏时正常铺满。四条轨道从顶部到底部均可触控，点击位置与画面上的透视轨道对应。
5. 下方为横跨四轨的双线判定框，音符到达框的下沿时踩点。可在对应轨道任意高度点击或长按；长按保持至尾部到达下沿；暖黄色滑动音符使用大号实心双箭头，从对应轨道起手，按方向短划至少 24 CSS 像素。轨道会越过判定框继续向下延展，未击中的音符穿过后淡出。
6. 歌曲结束后查看成绩，重试或返回选歌。自动演示可观察谱面，不记录最佳分数；进入后可在顶栏开启“落点音”，直接试听当前谱面的音符头，默认关闭。同刻多押只响一次，长按尾部不响。

取消从音频时长探测、文件读取和音频准备阶段即可生效；取消会清除当前歌曲引用，迟到结果不会替换新歌。原生 `decodeAudioData` 没有取消接口，因此读取/解码串行执行：取消后可立即操作页面，但下一首需要等正在执行的原生解码实际结束，不会同时启动多个整曲解码。排队及读取/解码共用 45 秒等待上限，持续无响应时给出刷新重试提示。准备期间切换增强/轻量只更新选择，不重复准备同一首歌。

高采样率音频按 4 秒片段处理，每片保留 50 ms 滤波预热，全局样本位置保持连续；仍使用原来的八阶抗混叠低通。96 kHz / 5 分钟样本中，单个高采样率临时缓冲从整曲的 115.2 MB 减为最多 1.56 MB，整曲原始播放缓冲和最终分析副本仍需保留；这不是整页内存峰值。低采样率升采样保留完整原生插值，不重置分段相位。取消会停止调度后续片段并断开当前音频节点，具体内存回收时间由浏览器决定。

击中单点时，整个音符块会亮起并碎散消失；长按成功起手后，光带持续产生电弧和向上移动的脉冲，尾部完成时再闪亮一次；滑动额外带有方向光迹。特效围绕对应轨道与判定框绘制，不使用全屏闪白或震屏。

「音量、震动与校准」提供击打震动开关、音量、−300～+300 ms 判定偏移以及 BPM 修正。设备和浏览器支持 `navigator.vibrate` 时，手动成功击中会触发 10～16 ms 短震，长按首尾均有反馈，同时按键会合并震动；自动演示和 Miss 不震动。关闭开关或不支持此 API 时仍可正常游玩。正偏移代表判定时刻更晚，负偏移更早。未修改 BPM 的“重新生成”保留自动局部拍点；修改后按固定 BPM 参考重新选择实际起音，可用“恢复自动拍点”撤销。它不改变歌曲播放速度。

| 指法难度 | 谱面规则 |
| --- | --- |
| 单指 | 单指轮换，无同时按键；长按期间不插入其他操作。 |
| 二指 | 最多二指同时操作，可双押或长按搭配单点。 |
| 三指 | 最多三指同时操作，包含三押和更多长按配合。 |
| 四指 | 最多四指同时操作，重音可出现四轨同时按键。 |

每张谱面会显示所选档位、实际用指峰值、候选拍点和动作路线检查结果。安静、重音较少的歌曲不强行塞入多押，因此峰值可能低于档位上限。多押仍安排在实际检测到的声音起点，服从现有手指占用。首次访问默认二指，旧版简单/普通/困难分别迁移为二指/三指/四指，其余设置保留。

动作路线检查基于统一触控高度的参考手部模型：移动距离越远，需要的换指时间越多；长按中的手指保持占用，其他手指不能直接穿过。采用宽度 24 的束搜索，优先调整落轨，保留音乐时间；所有搜索分支都无法延续时才省略音符。该模型没有标定个人手长和具体手机宽度，实际舒适度仍需真机体验。

纯算法按实测起音和连续拍点给已选主线添加主拍、半拍及细分角色，优先保留较轻的主拍，不让响亮装饰音挤掉它；没有角色证据的起音沿用强度规则。来源交接会检查旧周期和相位，减少后段被另一层声音带走。文件开头的边界提示单独处理，不干扰后续节奏推断。模型辅助则用本地模型提供拍点参考。两条路径的长按都需要新出现并持续的音高能量，滑动与多押按重音和乐句编排。相似段落在节奏、音高及持续发音证据足够一致时复用按键模板，并保持各次实际起点；所有档位最后规划整段手指路线。完整实现和边界见 [ALGORITHM.md](ALGORITHM.md)。

单点、滑动与长按起点的 Perfect 为 ±45 ms，Great 为 ±90 ms，Good 为 ±140 ms，超时为 Miss。权重分别为 1、0.75、0.4、0。长按持续到尾部自动获得尾部 Perfect，无需精准松手；提前松手则失去尾部得分并记 Miss。长按首尾各为一个等权判定单位。分数归一化为 100 万，准确率为已判定单位的加权平均，Miss 中断连击。

判定规则版本 2 修正了早松 90 ms 仍获 Perfect 的旧宽限，按原计划要求持到尾部。最佳成绩按谱面版本、判定规则版本、识别引擎、歌曲、指法、BPM 与参考网格分别保存。旧记录不会删除，新规则不会与旧宽限下的成绩混比。历史最佳只接受 0～100 万的整数，损坏记录不影响游玩；存储被禁用时也可正常生成谱面。

手动暂停、切后台、系统取消触点或游玩中改变屏幕方向会暂停音乐和谱面。竖屏进入游戏时可直接游玩。恢复前倒计时 3 秒；如暂停时存在长按，需在倒计时内重新按住原轨道，未重新按住的长按尾部会判为 Miss。自动演示不需要重新按住。全屏是可选功能，浏览器不支持时仍可正常游玩。

暂停会保存本局歌曲位置并停止当前声源，即使浏览器的音频上下文被其他调用恢复，暂停的歌曲也不会自行前进。点击继续时先在按钮事件内恢复声音，成功后才开始 3 秒倒计时；声音恢复超过 8 秒会回到可重试的暂停菜单。重新开始、再次暂停、切后台或退出会作废上一轮恢复结果，迟到的成功或失败不能影响新一局。首次开始或自动演示也有 8 秒恢复声音上限；等待期间换歌或更换谱面，不会被旧启动请求带入游戏。

右上角固定提供全屏按钮，选歌、游戏和结算时均可使用；进入全屏后点击同一位置退出。不支持全屏的浏览器会显示提示并继续保持横向页面布局。

## GitHub Pages

网站地址为 **https://broken-star1999.github.io/musicgame/**。

`.github/workflows/pages.yml` 会在推送到 `main` 时自动安装依赖、运行测试、构建，并发布 `dist` 到 GitHub Pages。仓库的 Settings → Pages → Source 使用 **GitHub Actions**。也可以在 Actions 中手动运行该工作流。

模型、WASM、字体和 Worker 都是网站自身的静态资源。Vite 使用相对资源路径 `base: './'`，使脚本、字体、图标和分析 Worker 同时适配 GitHub Pages 的 `/musicgame/` 子目录与 EdgeOne 的根目录。页面内部切换菜单与游戏，不需要服务端路由。

## 部署到 EdgeOne Makers

项目是纯静态应用，不需要 API Key、服务端或数据库。先把源码上传到自己的 GitHub 仓库，**不要上传 `node_modules`、`dist`、`.qa` 或个人音频/视频文件**。这些目录已加入 `.gitignore`。

在 EdgeOne Makers 中选择「导入 Git 仓库」，连接 GitHub 并选择项目：

| 设置 | 值 |
| --- | --- |
| 根目录 | 仓库根目录 |
| 安装命令 | `npm ci` |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| Node.js | `22.11.0`（官方列出的预装 Node 22 版本） |
| 环境变量 | 无 |

这些构建参数也写入了根目录 `edgeone.json`。使用 HTTPS 部署，发布后检查首页、Worker 加载、音频导入和完整演奏流程。应用使用单页内部状态切换，没有需要单独配置回源的子路由。

可参考 [EdgeOne Git 部署说明](https://edgeone.ai/document/70404) 和 [edgeone.json 配置说明](https://pages.edgeone.ai/document/edgeone-json)。GitHub Pages 与 EdgeOne 可共用此仓库；EdgeOne 部署由仓库所有者在腾讯控制台连接后进行。

手机测试本地服务时，可以运行 `npm run dev -- --host 0.0.0.0`，在同一局域网用电脑的局域网地址访问。正式部署的 HTTPS 地址更适合验证手机兼容性。

## 实现结构

- `src/core/analysis.ts`：使用 fft.js 计算 1024 点实数 FFT，结合频率邻域最大值抑制、低/中/高频正向频谱变化、自适应阈值和局部峰值检测。用实际声音起点的间隔估计 BPM，并返回节拍支持度、能量包络和音频指纹。`analysis.worker.ts` 将计算放在 Web Worker 中。
- `src/core/beat-features.ts`、`beat-inference.ts`、`beat-decoder.ts`：模型特征、单线程 WASM 推理、块合并及保守拍点解码。
- `src/core/musical-events.ts` 与 `recognition.ts`：将模型拍点绑定到实际起音并赋予节奏层次。
- `src/core/onset-selection.ts`：先保留主拍骨架，再按层次和强度筛选落点。
- `src/core/rhythm-source.ts`：分段比较频段起音的周期支持度，以切换代价保持节奏来源连续；不把频段当成乐器身份。
- `src/core/chroma.ts` 与 `rhythm.ts`：4096 点独立音高特征、局部自相关、连续拍点动态规划、局部速度及弱支持度回退。
- `src/core/chart.ts`：从实际起点生成稳定的谱面；有限对齐节拍，基于持续能量编排长按，基于重音编排滑动；限制同轨间隔、长按重叠和同时操作数量。相同浏览器解码结果及难度产生相同谱面。
- `src/core/patterns.ts` 与 `phrases.ts`：原创乐句模式、持续音候选、拍坐标中的重复匹配与有界 DTW；限制比较数量，避免密集歌曲产生无界两两比较。
- `src/core/fingering.ts`：整段束搜索和显式手指分配回放，处理移动时间、长按阻挡、交叉及连续负担。
- `src/core/chart.worker.ts` 与 `chart-service.ts`：可取消的异步编谱，释放 Worker 并拒绝迟到结果。
- `src/core/chart-constraints.ts`：统一的用指占用、实际峰值及整张谱面可操作性检查；同时用于模板复用检查和页面统计。
- `src/core/judgment.ts`：独立、可测试的判定状态机，处理长按首尾、手势方向、暂停后长按重抓和分数。
- `src/core/haptics.ts`：可选的短震反馈、同时击打合并与暂停清理。
- `src/core/beat-cues.ts`：自动演示可选落点提示音，按本局音频时间线预调度，暂停/关闭/退出清理；不参与判定，不改变歌曲速度。
- `src/core/audio.ts` 与 `audio-decode.ts`：本地原创演示曲、分段抗混叠降采样、可取消文件读取与串行解码。
- `src/core/demo-synthesis.ts`、`demo.worker.ts` 与 `demo-service.ts`：保持原 PCM 的异步原创演示曲合成、可取消任务、30 秒总超时和 Worker 清理。
- `src/core/analysis-result.ts`：增强结果的白名单增量消息，复用已收到的基础特征数组。
- `src/core/audio-transport.ts` 与 `game-recovery.ts`：以 `AudioContext.currentTime` 为基准的本局播放位置、声源暂停/恢复、手势内声音启用、倒计时与异步结果归属。
- `src/components/Game.tsx` 与 `renderer.ts`：Pointer Events 多触点追踪、暂停恢复和 Canvas 2D 透视舞台。音符位置由时间直接计算，丢帧不会累积位移误差。舞台光效参考已分析的能量包络。

内部谱面生成版本为 9：识别路径、音频指纹、指法难度、手指上限、时长、BPM、音符列表、乐句复用统计和指法规划报告。难度标识为 `one | two | three | four`。音符包含编号、0～3 轨道、秒单位时间及 `tap | hold | left | right | up` 类型；长按包含结束时间，最终音符额外记录 `finger` 分配。最佳成绩按生成版本、识别路径、指法和参考网格分别记录，不混用旧版成绩。无公共后端 API。完整算法及参考来源见 [ALGORITHM.md](ALGORITHM.md)。

音频、分析数据和谱面只在当前页面内存中保留。只有设置与最佳分数进入 `localStorage`；刷新后需重新导入歌曲。CacheStorage 只保存经过校验的公开模型和 WASM，当前两项共约 24 MB，不保存个人音乐。字体、图标和程序资源随构建打包，不依赖运行时字体 CDN。演示曲为程序原创合成，个人歌曲与参考视频未放入源码或构建产物。

自动谱面属于信号分析和游戏编排，不是精确的乐器转录或人工谱。复杂变拍、弱鼓点、混响较强的曲目可能有偏差；不同浏览器的解码/重采样细节也可能导致少量音符差异。

## 验证

`npm test` 覆盖已知 BPM 的合成鼓点、前置静音、变速片段、静音/极低音量拒绝、50 ms 起点误差目标、谱面可重复性、同轨冲突、难度上限、判定边界、四轨独立输入、滑动方向、长按松手、暂停后重抓及自动演示。

可使用本地歌曲执行额外分析测试，需要已安装 `ffmpeg`，歌曲路径通过临时环境变量提供，不复制歌曲到仓库：

```powershell
$env:BEATFALL_TEST_AUDIO = 'C:\path\to\your-song.flac'
npm test
```

该测试会输出 BPM、起点数量、四档音符分布和实际用指峰值，并检查同轨间隔、时长边界、长按与滑动占用、同时操作上限和重复生成。FFmpeg 与浏览器的重采样路径不同，数量可能略有差异。

当前版本10的414项核心测试通过，另有一个私有歌曲项默认跳过；数据比较工具还有11项原生Node检查。选源在没有支持时可以放弃，最终谱面不能只剩文件开头的不确定提示。真实浏览器三个采样率的噪声WAV均可恢复拒绝，正常弱段与《九万字》四档保留；另一次预冻结新30段回归的指标、四指数量和身份均不变。旧150段中有一段少了一个候选支持头，取舍及边界完整保留在 [来源与谱面有效性验证](benchmarks/SOURCE_AUDIT.md)。此前弱段修正和仍未采用的节拍方案见 [弱段诊断](benchmarks/DYNAMICS_AUDIT.md)、[周期与角色实验](benchmarks/TEMPO_EVIDENCE.md)；未宣称一般音乐识别问题已解决。

历史版本 8 的纯算法在预先固定的 30 段新音乐比较中，单指 ±70 ms 头 F1 从 0.5218 到 0.5990，20 段改善、8 段退步、2 段不变；推断拍点 F1 保持不变，四指平均实测起手数量未减少。它衡量主拍选择兼容性，不是游戏内准确率或全部歌曲的正确率；冻结规则、完整退步和复现步骤见 [纯算法验证](benchmarks/SIGNAL_AUDIT.md)。

历史版本 7 在桌面 Edge 中用《九万字 - 黄诗扶》FLAC 完成实际 WASM 分析，约 232 秒的歌曲一次分析约 21.9 秒；四档生成和操作约束检查通过。估计 BPM 为 130，不是人工确认的官方 BPM。该版的 325 项常规测试包含实际 WASM 与上游参考值对照、资源下载超时、页面侧 Worker 保护、可选资源缓存、音频准备/解码取消、本局播放/恢复归属、存储异常、长按尾部边界和落点音调度，私有歌曲测试默认跳过；设置环境变量后，该项也运行模型。分段预处理在该曲上的分析 PCM 与原路径逐样本一致。另一次真实浏览器增强分析加四档重编约 21.5 秒，并导出仅本地的五段 8 秒试听供人工对照。没有对这首歌完成逐音符人工听感标注。

两项后续算法原型未通过客观验证，未进入生产；其中固定规则的九间隔中位数绑定容差在另一批 30 段的单指头 F1 从 0.754223 降到 0.751101，0 升、3 降、27 不变。问题定位、拒绝原因、新样本出处与复核脚本见 [质量诊断记录](benchmarks/QUALITY_AUDIT.md)。Beat-reference F1 不是游戏内准确率，也不代表完整的主观听感。

30 段、10 种风格的 GTZAN 开发比较中，±70 ms 节拍 F1 从版本 6 的 0.682 提升到 0.843；21 段改善、4 段持平、5 段退步。这不是全数据集的官方指标，也不是游戏准确率。逐曲结果与复现步骤见 [benchmarks/README.md](benchmarks/README.md)。

桌面 Edge 已检查完整导入、取消、恢复、触控、结算和重试；Android Chrome/Edge、iPhone Safari 的真实四指手感、蓝牙延迟、音频恢复与资源开销仍待真机验证。

详细验证结果见 [QA_REPORT.md](QA_REPORT.md)，逐项交付核对见 [DELIVERY_CHECKLIST.md](DELIVERY_CHECKLIST.md)。轨道穿过双线判定框延展到画布底部；渲染与整轨触控共用透视几何计算，保证视觉边界与操作归属一致。

## 模型导出（仅开发者可选）

发布用模型已随源码提供，普通构建只需 `npm ci && npm run build`，不会运行 Python 或重新训练。若需重做导出，可在独立 Python 环境中先从官方 CPU 索引安装 Torch/Torchaudio 2.9.1，再安装 `scripts/beat-model-requirements.txt`，运行 `python scripts/export-beat-model.py`。脚本校验上游权重 SHA-256、原生推理及多种块长度的一致性，再写入带内容哈希的模型和配置；许可保留于 `public/models/BEAT_THIS_LICENSE.txt`。导出仅作转换，不训练权重。
