# 节拍坠落 / Beatfall

当前网站**只使用纯算法**：频谱起音检测、节奏来源选择、局部拍点跟踪和确定性编谱。神经网络推理、模型辅助选项、权重文件、ONNX/WASM 运行库及导出脚本已移除；导入音乐只在浏览器本地处理。

当前谱面版本12补齐了虚拟节拍时钟的尾部边界：被门控排除的末尾起音不能继续延长时钟，内部休止仍保持连续。六条源码回归测试覆盖该修复；原210段歌曲对比中全部节拍和谱面不变，证明未回归，不代表这210段的识别准确率提高。完整证据与限制见[尾部边界验证](benchmarks/CLOCK_TAIL_V12.md)。新旧谱面成绩按版本分别保存。

版本11的纯算法主线曾在一次预冻结新30段验证中，将单指主拍兼容F1（±70ms）由0.562607提升到0.680515，22段提升、5段下降、3段相同；该批预声明发布门槛通过。节拍层级及相位反例仍存在，完整边界和退步见[版本11验证](benchmarks/PHASE_V11_RELEASE.md)。

后续真实钢琴案例暴露了更多主拍预测带来的精度下降，其中一段的四项预定主指标未通过。对210段已观察音乐的开发诊断也未支持三种新候选，它们均未进入游戏。完整逐段结果、四指保留与跟拍／按键绑定的归因见[变速与复调审计](benchmarks/RUBATO_V11_AUDIT.md)。

后续跟拍输入、局部脉冲与选键实验仍存在明显取舍，临时的 R v12 开发草案已回退，本轮保留 v11。六种方案的实现补丁、完整退步数据及频带证据边界见[节拍证据与编谱选择审计](benchmarks/CLOCK_SELECTION_AUDIT.md)。

新的频谱与瞬态实验区分了起音检测帧和后续能量峰。T2 在一个开发片段改善明显，但 210 段比较中的单指主拍 F1 从 0.692744 降到 0.677905，因此该 v12 草案也已归档回退；运行代码仍为 v11。提取层物理回归、完整代码补丁、全部退步及实际浏览器流程边界见[瞬态证据验证](benchmarks/TRANSIENT_EVIDENCE_AUDIT.md)。这是移除前 v11 的历史基线（449 项通过、1 项私有歌曲跳过）；本轮纯算法移除版的验证状态见 [QA_REPORT.md](QA_REPORT.md)。

## 纯算法处理

本地音频经 Web Audio 解码、单声道抗混叠准备后，分析 Worker 通过 FFT 频谱变化寻找起音、选择连贯节奏来源并跟踪局部拍点；编谱 Worker 再按单指至四指的占用与动作约束安排音符。没有识别方式开关、模型准备、权重下载或推理阶段。

原创演示曲也由可取消的 Worker 合成。菜单预览最多 30 FPS，分析、离屏、后台、弹窗遮挡或系统减少动画时停止循环；游玩始终使用音频时间判定。手机实际运行速度和总内存仍需真机验证，历史桌面记录见 [手机加载验证](benchmarks/MOBILE_PERFORMANCE.md)，其中旧功能的描述只对应当时版本。

## 使用方法

1. 导入 MP3、WAV、M4A、OGG 或 FLAC 文件。最大 50 MB，时长 2 秒至 5 分钟；具体格式支持由浏览器决定。也可以直接使用内置演示曲。
2. 选择单指、二指、三指或四指，切换后在 Worker 中重新编谱，预览、游戏及结算显示同一档位。四档都使用四条轨道；除长按与滑动占用外，还会规划每根手指的落位、移动时间及交叉关系。生成时可取消，切换指法会终止旧任务。
3. 选择下落方式和速度。默认「透视推进」随轨道变宽平滑加速，使每秒位移与当前轨道宽度的比例保持一致；「屏幕匀速」保持恒定的屏幕纵向像素速度。两种方式都在同一时间到达判定线，速度设置只影响视觉提前量，不改变音乐节奏。
4. 网页默认使用横向布局，选歌、设置、游戏和结算保持同一方向。手机锁定竖屏时整页会自动侧转 90°，无需关闭系统旋转锁；自然横屏时正常铺满。四条轨道从顶部到底部均可触控，点击位置与画面上的透视轨道对应。
5. 下方为横跨四轨的双线判定框，音符到达框的下沿时踩点。可在对应轨道任意高度点击或长按；长按保持至尾部到达下沿；暖黄色滑动音符使用大号实心双箭头，从对应轨道起手，按方向短划至少 24 CSS 像素。轨道会越过判定框继续向下延展，未击中的音符穿过后淡出。
6. 歌曲结束后查看成绩，重试或返回选歌。自动演示可观察谱面，不记录最佳分数；进入后可在顶栏开启“落点音”，直接试听当前谱面的音符头，默认关闭。同刻多押只响一次，长按尾部不响。

取消从音频时长探测、文件读取和音频准备阶段即可生效；取消会清除当前歌曲引用，迟到结果不会替换新歌。原生 `decodeAudioData` 没有取消接口，因此读取/解码串行执行：取消后可立即操作页面，但下一首需要等正在执行的原生解码实际结束，不会同时启动多个整曲解码。排队及读取/解码共用 45 秒等待上限，持续无响应时给出刷新重试提示。

高采样率音频按 4 秒片段处理，每片保留 50 ms 滤波预热，全局样本位置保持连续；仍使用原来的八阶抗混叠低通。96 kHz / 5 分钟样本中，单个高采样率临时缓冲从整曲的 115.2 MB 减为最多 1.56 MB，整曲原始播放缓冲和最终分析副本仍需保留；这不是整页内存峰值。低采样率升采样保留完整原生插值，不重置分段相位。取消会停止调度后续片段并断开当前音频节点，具体内存回收时间由浏览器决定。

击中单点时，整个音符块会亮起并碎散消失；长按成功起手后，光带持续产生电弧和向上移动的脉冲，尾部完成时再闪亮一次；滑动额外带有方向光迹。特效围绕对应轨道与判定框绘制，不使用全屏闪白或震屏。

「音量、震动与校准」提供击打震动开关、音量、−300～+300 ms 判定偏移以及 BPM 修正。设备和浏览器支持 `navigator.vibrate` 时，手动成功击中会触发 10～16 ms 短震，长按首尾均有反馈，同时按键会合并震动；自动演示和 Miss 不震动。关闭开关或不支持此 API 时仍可正常游玩。正偏移代表判定时刻更晚，负偏移更早。未修改 BPM 的“重新生成”保留自动局部拍点；修改后按固定 BPM 参考重新选择实际起音，可用“恢复自动拍点”撤销。它不改变歌曲播放速度。

| 指法难度 | 谱面规则 |
| --- | --- |
| 单指 | 单指轮换，无同时按键；长按期间不插入其他操作。 |
| 二指 | 最多二指同时操作，可双押或长按搭配单点。 |
| 三指 | 最多三指同时操作，包含三押和更多长按配合。 |
| 四指 | 最多四指同时操作，重音可出现四轨同时按键。 |

每张谱面会显示所选档位、实际用指峰值、候选拍点和动作路线检查结果。安静、重音较少的歌曲不强行塞入多押，因此峰值可能低于档位上限。多押仍安排在实际检测到的声音起点，服从现有手指占用。首次访问默认二指，旧版简单/普通/困难分别迁移为二指/三指/四指，其余设置保留。

动作路线检查基于统一触控高度的参考手部模型：移动距离越远，需要的换指时间越多；长按中的手指保持占用，其他手指不能直接穿过。采用宽度 24 的束搜索，优先调整落轨，保留音乐时间；所有搜索分支都无法延续时才省略音符。该模型没有标定个人手长和具体手机宽度，实际舒适度仍需真机体验。

纯算法按实测起音和连续拍点给已选主线添加主拍、半拍及细分角色，优先保留较轻的主拍，不让响亮装饰音挤掉它；没有角色证据的起音沿用强度规则。来源交接会检查旧周期和相位，减少后段被另一层声音带走。文件开头的边界提示单独处理，不干扰后续节奏推断。长按需要新出现并持续的音高能量，滑动与多押按重音和乐句编排。相似段落在节奏、音高及持续发音证据足够一致时复用按键模板，并保持各次实际起点；所有档位最后规划整段手指路线。完整实现和边界见 [ALGORITHM.md](ALGORITHM.md)。

单点、滑动与长按起点的 Perfect 为 ±45 ms，Great 为 ±90 ms，Good 为 ±140 ms，超时为 Miss。权重分别为 1、0.75、0.4、0。长按持续到尾部自动获得尾部 Perfect，无需精准松手；提前松手则失去尾部得分并记 Miss。长按首尾各为一个等权判定单位。分数归一化为 100 万，准确率为已判定单位的加权平均，Miss 中断连击。

判定规则版本 2 修正了早松 90 ms 仍获 Perfect 的旧宽限，按原计划要求持到尾部。最佳成绩按谱面版本、判定规则版本、固定的纯算法生成标识、歌曲、指法、BPM 与参考网格分别保存。旧记录不会删除，新规则不会与旧宽限下的成绩混比。历史最佳只接受 0～100 万的整数，损坏记录不影响游玩；存储被禁用时也可正常生成谱面。

手动暂停、切后台、系统取消触点或游玩中改变屏幕方向会暂停音乐和谱面。竖屏进入游戏时可直接游玩。恢复前倒计时 3 秒；如暂停时存在长按，需在倒计时内重新按住原轨道，未重新按住的长按尾部会判为 Miss。自动演示不需要重新按住。全屏是可选功能，浏览器不支持时仍可正常游玩。

暂停会保存本局歌曲位置并停止当前声源，即使浏览器的音频上下文被其他调用恢复，暂停的歌曲也不会自行前进。点击继续时先在按钮事件内恢复声音，成功后才开始 3 秒倒计时；声音恢复超过 8 秒会回到可重试的暂停菜单。重新开始、再次暂停、切后台或退出会作废上一轮恢复结果，迟到的成功或失败不能影响新一局。首次开始或自动演示也有 8 秒恢复声音上限；等待期间换歌或更换谱面，不会被旧启动请求带入游戏。

右上角固定提供全屏按钮，选歌、游戏和结算时均可使用；进入全屏后点击同一位置退出。不支持全屏的浏览器会显示提示并继续保持横向页面布局。

## 实现结构

- `src/core/signal-analysis.ts` 与 `analysis.ts`：使用 fft.js 计算 1024 点实数 FFT，结合频率邻域最大值抑制、低/中/高频正向频谱变化、自适应阈值和局部峰值检测。用实际声音起点的间隔估计 BPM，并返回节拍支持度、能量包络和音频指纹。`analysis.worker.ts` 将计算放在 Web Worker 中。
- `src/core/musical-events.ts` 与 `signal-binding.ts`：将算法拍点参考绑定到实际起音并赋予节奏层次。
- `src/core/onset-selection.ts`：先保留主拍骨架，再按层次和强度筛选落点。
- `src/core/rhythm-source.ts`：分段比较频段起音的周期支持度，以切换代价保持节奏来源连续；不把频段当成乐器身份。
- `src/core/chroma.ts` 与 `rhythm.ts`：4096 点独立音高特征、局部自相关、连续拍点动态规划、局部速度及弱支持度回退。
- `src/core/chart.ts`：从实际起点生成稳定的谱面；有限对齐节拍，基于持续能量编排长按，基于重音编排滑动；限制同轨间隔、长按重叠和同时操作数量。相同浏览器解码结果及难度产生相同谱面。
- `src/core/patterns.ts` 与 `phrases.ts`：原创乐句模式、持续音候选、拍坐标中的重复匹配与有界 DTW；限制比较数量，避免密集歌曲产生无界两两比较。
- `src/core/fingering.ts`：整段束搜索和显式手指分配回放，处理移动时间、长按阻挡、交叉及连续负担。
- `src/core/chart.worker.ts` 与 `chart-service.ts`：可取消的异步编谱，释放 Worker 并拒绝迟到结果。
- `src/core/chart-constraints.ts`：统一的用指占用、实际峰值及整张谱面可操作性检查；同时用于模板复用检查和页面统计。
- `src/core/judgment.ts`：独立、可测试的判定状态机，处理长按首尾、手势方向、暂停后长按重抓和分数。
- `src/core/haptics.ts`：可选的短震反馈、同时击打合并与暂停清理。
- `src/core/beat-cues.ts`：自动演示可选落点提示音，按本局音频时间线预调度，暂停/关闭/退出清理；不参与判定，不改变歌曲速度。
- `src/core/audio.ts` 与 `audio-decode.ts`：本地原创演示曲、分段抗混叠降采样、可取消文件读取与串行解码。
- `src/core/demo-synthesis.ts`、`demo.worker.ts` 与 `demo-service.ts`：保持原 PCM 的异步原创演示曲合成、可取消任务、30 秒总超时和 Worker 清理。
- `src/core/audio-transport.ts` 与 `game-recovery.ts`：以 `AudioContext.currentTime` 为基准的本局播放位置、声源暂停/恢复、手势内声音启用、倒计时与异步结果归属。
- `src/components/Game.tsx` 与 `renderer.ts`：Pointer Events 多触点追踪、暂停恢复和 Canvas 2D 透视舞台。音符位置由时间直接计算，丢帧不会累积位移误差。舞台光效参考已分析的能量包络。

内部谱面生成版本为 12：纯算法生成标识、音频指纹、指法难度、手指上限、时长、BPM、音符列表、乐句复用统计和指法规划报告。难度标识为 `one | two | three | four`。音符包含编号、0～3 轨道、秒单位时间及 `tap | hold | left | right | up` 类型；长按包含结束时间，最终音符额外记录 `finger` 分配。最佳成绩按生成与判定版本、歌曲、指法和参考网格分别记录，当前仅使用纯算法命名空间。无公共后端 API。完整算法及参考来源见 [ALGORITHM.md](ALGORITHM.md)。

音频、分析数据和谱面只在当前页面内存中保留。只有设置与最佳分数进入 `localStorage`；刷新后需重新导入歌曲。不再下载或缓存权重/WASM。升级时仅尽力删除旧版专用资源缓存，不清空其他应用缓存或歌曲最佳成绩。字体、图标和程序资源随构建打包，不依赖运行时字体 CDN。演示曲为程序原创合成，个人歌曲与参考视频未放入源码或构建产物。

自动谱面属于信号分析和游戏编排，不是精确的乐器转录或人工谱。复杂变拍、弱鼓点、混响较强的曲目可能有偏差；不同浏览器的解码/重采样细节也可能导致少量音符差异。

## 验证

`npm test` 覆盖已知 BPM 的合成鼓点、前置静音、变速片段、静音/极低音量拒绝、50 ms 起点误差目标、谱面可重复性、同轨冲突、难度上限、判定边界、四轨独立输入、滑动方向、长按松手、暂停后重抓及自动演示。

可使用本地歌曲执行额外分析测试，需要已安装 `ffmpeg`，歌曲路径通过临时环境变量提供，不复制歌曲到仓库：

```powershell
$env:BEATFALL_TEST_AUDIO = 'C:\path\to\your-song.flac'
npm test
```

该测试会输出 BPM、起点数量、四档音符分布和实际用指峰值，并检查同轨间隔、时长边界、长按与滑动占用、同时操作上限和重复生成。FFmpeg 与浏览器的重采样路径不同，数量可能略有差异。

历史版本10的414项核心测试通过，另有一个私有歌曲项默认跳过；数据比较工具还有12项原生Node检查。选源在没有支持时可以放弃，最终谱面不能只剩文件开头的不确定提示。真实浏览器三个采样率的噪声WAV均可恢复拒绝，正常弱段与《九万字》四档保留；另一次预冻结新30段回归的指标、四指数量和身份均不变。旧150段中有一段少了一个候选支持头，取舍及边界完整保留在 [来源与谱面有效性验证](benchmarks/SOURCE_AUDIT.md)。此前弱段修正和仍未采用的节拍方案见 [弱段诊断](benchmarks/DYNAMICS_AUDIT.md)、[周期与角色实验](benchmarks/TEMPO_EVIDENCE.md)；未宣称一般音乐识别问题已解决。

历史版本 8 的纯算法在预先固定的 30 段新音乐比较中，单指 ±70 ms 头 F1 从 0.5218 到 0.5990，20 段改善、8 段退步、2 段不变；推断拍点 F1 保持不变，四指平均实测起手数量未减少。它衡量主拍选择兼容性，不是游戏内准确率或全部歌曲的正确率；冻结规则、完整退步和复现步骤见 [纯算法验证](benchmarks/SIGNAL_AUDIT.md)。

旧辅助推理功能及其验证记录保留在 [移除前的历史提交](https://github.com/broken-star1999/musicgame/blob/82c9905/QA_REPORT.md) 和 benchmarks 归档中；它们不是当前网站的依赖或运行能力。历史实验需检出相应提交复现。
