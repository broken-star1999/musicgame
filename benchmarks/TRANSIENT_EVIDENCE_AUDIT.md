## F/F2 证明了什么

F 在原 FFT 的同一次幅值循环中记录三频带原始功率、归一化谱质心、谱集中度，以及低频功率在一窗前后的升降。它们描述当时的完整音频帧，并非分离出的乐器。仅给保留的真实起音附元数据；文件左边界 f0 不进入推断，缺少前后文会明确标记未知。新增六个 Float64 帧数组，48 字节/帧，无额外 FFT；22050 Hz、300 秒、hop 221 对应 29928 帧，额外 typed storage 1436544 字节，另有对象堆内存开销。

F/F2 各覆盖原 36 段合成控制和 5 首已观察音乐：36 个成功输入、5 个相同正常拒绝。移除明确新增的 `acoustic` 字段后，旧完整 Analysis JSON 均逐字节相等；144 对完整 Chart JSON 相等。F2 仅移除新增嵌套字段后，还与旧 F 的全部当前帧字段精确相等。独立直接 DFT、实际 FFT、固定增益、静音、边界与未知前后文检查通过。**这些证明提取和兼容性，不证明音乐识别变准。**

原 T 在起音触发帧直接比较后续低频功率。实际起音检测可能发生在能量仍上升时，短起音因此被记为零衰减。F2 在完整的一窗范围内找最早的低频功率最大值，另存峰偏移，读取峰后一窗的功率；保留原起音时间，不把峰位置偷偷写成音符时间。窗口不完整就省略描述，缺失上下文仍为未知。

四组实际 canonical 检测的合成低频 burst 各有 8 次起音，全部定位误差不超过 28.06 ms。F2 的新乘积均为正，但强度存在边界：

| burst 长度 | 正值次数 | 最小乘积 |
|---|---:|---:|
| 11.6 ms | 8/8 | 0.997534 |
| 23.2 ms | 8/8 | 0.999179 |
| 46.4 ms | 8/8 | 0.999986 |
| 92.9 ms | 8/8 | 0.000016771 |

最长组仍可落在近平台上。正数不等于强衰减，也不证明任意音长或乐器都能识别。固定唯一峰波形的 0.1/0.3/1 增益检查通过，并不声称任意数值近平台的 argmax 都不变。

## 两个消费者与小样本结果

T 把当前帧 `lowFraction × lowRise × lowDecay` 加到同一事件的原归一化幅度，再做原 Gaussian/max 投影。T2 改用新峰上下文的乘积。它们保留原起音集合、时间、来源调查、局部速度、旧投影证据和判定公式；没有删除旧证据或强制置信度为 1。

T 在五首已观察歌曲上的 Head70/Clock70 平均增益均为 0，未通过小样本门槛，没有扩大测试。其冻结源码另外存在 **TS6133**：`oldEnvelope`、`bonuses` 未使用。补丁保留原样；esbuild 实验可运行，不代表该 T 补丁能通过项目严格 TypeScript 构建。未修好它再冒称原冻结版本。

T2 的五首小样本 Head70 平均由 0.512817 升到 0.631897，Clock70 由 0.480293 升到 0.599296，通过预写小样本筛选，因此移植实际 v12 草案并扩大到 210 段。小样本属于已观察开发数据，五首也包含在这 210 段内，不能算独立验证。

## 实际 T2 的 210 段结果

七组各 30 段，沿用原十个曲风和相同音频、参考数据、匹配方法及所有四种指法。基线为发布的 067e050/v11；候选是实际源码 v12。配套程序重新验证 stock/trace、原始物理字段与完整谱面哈希；没有只把新分析接到旧 chart support 上。

| 指标 | v11 | T2 草案 | 配对平均差 |
|---|---:|---:|---:|
| 单指 Head50 F1 | 0.633062 | 0.620073 | −0.012989 |
| 单指 Head70 F1 | 0.692744 | 0.677905 | −0.014839 |
| Clock70 F1 | 0.723545 | 0.708483 | −0.015062 |

Head70 为 36 段提升、118 段不变、56 段下降。曲风最差 hiphop 平均差 −0.091039；最差片段 `hiphop.00011` 从 0.888889 降至 0.282828，差 −0.606061。四种指法 Head70 平均差依次为 −0.014839、−0.011078、−0.005516、−0.000705。

同为 hiphop，`00013` 从 0.039216 提升到 0.634615，`00011` 却大幅下降。两者前后 clock confidence 都低于 0.45，损益并非只发生于一次过阈值切换；canonical pulse 和回退起点也可能改变。这些结果不支持按已观察曲风、GT 或临时置信度阈值挑选开启条件。置信度是原公式的支持分，不是识别正确概率。

沿用[预写 19b 门槛的 PULSE 规则](clock-selection-qualification-nov1.json)：Head70、Clock70 各至少 +0.02，Head50 不降；每曲风至少 −0.03、每片段至少 −0.15、每片段四指测量音头数量比至少 0.95；原主控制单指不退步、所有模式合法且确定，物理输入与旧证据保持精确。T2 在平均指标、最差曲风、最差片段和四指数量方面均失败，没有豁免反例。

四指最低数量比 0.888889；`rock.00013`、`hiphop.00011`、`classical.00019` 共三段低于 0.95。38 段数量下降、87 段测量音头匹配下降，最低匹配比 0.816514。它衡量时间匹配，不等于整张谱或轨道完全相同。1680 个谱面全部通过可玩性、确定性和路线检查，单指长按冲突为零；工程合法不能替代踩点质量。

Head70 曲风内配对 bootstrap 95% 区间 **[−0.02933209, +0.00030652]** 包含零，不能据此声称总体显著变差；拒绝依据是当前开发数据和预写门槛。区间条件于固定十个曲风，不证明作品或艺人独立性。

210 个完整 clock 对象都不同，其中包含置信度变化，**不代表 210 条拍点路径全部不同**。实际使用 geometry 改变 101 段，canonical pulse membership 改变 79 段。原物理字段、候选、来源输入/路径、旧 clock 输入和旧 envelope 的 210 对比较均精确；420 对 stock/trace 与 1680 个官方完整谱面哈希相符。主输出版本 11/12 不归一化；20 个辅助副本仅改顶层版本号对照旧小样本，未改主输出或分数。

## 验证与交付边界

实际 v12 草案构建通过，454 项测试通过、1 项跳过；新增五项测试覆盖真实 FFT/实际 canonical 起音、增益、原时间不动、最早并列峰、完整窗口与未知上下文。桌面 Chromium 的生产 Worker 流程导入本地《九万字》，显示 3:52，单指 311 音符/29 长按；完整 AUTO 得分 100 万、340 Perfect、准确率 100%。这验证自动操作、长按尾、播放和结算流程，**不是音乐识别准确率**。也验证了快速指法切换、暂停恢复、取消后改用演示曲；没有上传音频或公开截图。

拒绝后恢复 v11，重新运行 449 通过/1 跳过、构建通过，三个运行 bundle 哈希与原发布精确相同。源码/构建配置恢复；原 210 条音频记录和此前 75 条诊断记录保持不变，仅新增七次完成的旧数据诊断，共 82 次。封存 30 段没有获准使用，实际调用被机械限制为旧 210 段；不可仅靠封存标志推断“未观察”。

未实际验证手机设备、多点触控/震动/codec 兼容矩阵或主观听感。本轮保留的是失败方案、物理定义修正和可复核证据，不能宣称音游算法问题已经解决。

三个补丁从 `ce301e0` 独立 scratch base 执行 `git apply --check` 和实际应用，全部目标文件逐字节核对。F 是提取层；T 保留已知严格编译错误；T2 补丁包含完整实际拒绝草案八文件和测试。它们供研究复核，**不建议应用到部署版本**。公开表格和 JSON 不含音频、真实 GT/anchor 时间数组、完整私有路径、签名 URL 或 wrapper 错误栈。
