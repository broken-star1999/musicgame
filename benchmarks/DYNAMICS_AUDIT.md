# 版本 9：弱段起音与算法诊断

基线为已发布的 `46ae43b517f8895333092df30dcdd7e95fb1a65f`（版本 8）。本次生产改动只移除综合/分频起音检测中的 `maxRms × 0.025` 排除条件，保留绝对 RMS `0.0008`、整曲静音检查、所有频谱/局部峰值/选源/拍点/角色和指法规则。谱面版本为 9，旧成绩保留并分开记录。模型及运行组件未修改。

## 实际修复的条件

当一段音乐先强后弱、先弱后强，或弱段中出现单个强音时，整曲最大值会使远处仍可检测的弱起音被排除。独立安排的 100Hz 鼓点 PCM 用于定位问题，参考时间来自合成调度，不来自 FFT、模型或当前检测器。

| 受控场景 | 修复前综合起音 | 修复后综合起音、主线和单指头 |
| --- | ---: | ---: |
| 前半正常，后半幅度 2% | 12/24 | 24/24 |
| 前半幅度 2%，后半正常 | 12/24 | 24/24 |
| 弱段中加入一次强音 | 25/48 | 48/48 |

所有目标匹配在 50ms 内。另有正常 10% 幅度控制、持续白噪声/振音曲尾和静音检查，共新增 7 项生产回归；修复前其中 3 项明确失败，修复后全通过。整套 404 项通过，私有歌曲项 1 项默认跳过。

独立预冻结的 9 个背景反例覆盖三档低幅白噪声/两个 seed、高通噪声、衰减噪声、持续振音，未发现新增 raw/pulse 或单指/四指尾部假头。反例噪声 RMS 实际位于旧相对门槛下、绝对门槛上，确实覆盖条件差异。这些受控样本不证明任意真实噪声都可区分。幅度降到 1% 的例子即使恢复原始起音，后续源选择和最低强度仍会丢失部分事件，没有宣称已解决全部弱音问题。

另一个未采用的 ±1 秒局部最大 RMS 原型，在强音前后仍漏掉弱拍：48 拍控制中的弱段为 18/24，而绝对门槛方案为 24/24，因此未使用局部最大值替代整曲最大值。

## 真实浏览器

最终生产构建在隔离 Edge 的 12 项检查通过。新增的 48kHz、16秒、16bit WAV 经原生解码和实际降采样/分析 Worker，四档都覆盖全部 24 个起音，其中 12 个幅度为 2%。单指24键，二/三/四指27/30/33键；额外多押都与真实起音同刻，路线检查通过，全谱重复 JSON 一致。

《九万字》实际原生导入到就绪约 2.99 秒，四档220/283/376/480键、分析 JSON 与版本 8 的本机记录一致，谱面只因版本号变化产生不同哈希。该时间是一次桌面观测，未当作手机性能。没有逐音符人工听辨整曲。

同时复查首次纯算法、自动/手动 BPM 及撤销、首边界时间、真实触控短曲结算、旧设置迁移、原 Worker 省略方式的默认行为、暂停退出。70个浏览器请求中66个服务器请求都是本源GET，ONNX/WASM、页面异常、HTTP失败均为0；4个元数据Object URL全部撤销。

## 尚未采用的变速改动

传统全局速度先验与动态规划的局限可参阅 [Ellis2007原论文](https://www.ee.columbia.edu/~dpwe/pubs/Ellis07-beattrack.pdf)，局部周期/相位表示参阅 [FMP PLP](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C6/C6S3_PredominantLocalPulse.html)。本项目另做了多候选局部周期及持久参考的两轮QA原型，没有进入生产。

第二轮在27个可辨识合成事件诊断中达到26项，完整PCM的100→180 BPM末段主头41/66→66/66，也守住追加八分音不能自动变成倍速的反例。然而，已观察开发30段的头F1仅0.602127→0.611313，12升9降9同；`hiphop.00019` 从0.444444降到0.050633，错误周期被角色优先放大。全局confidence反而从0.387升到0.587，不能将其当作正确概率。故未用平均小幅收益作为发布理由。

长休止的另一项审计也区分网格与最终头：120→150、休止20/90秒的V8完整PCM，最终四档头已是48/48，虽然低confidence导致备用网格末段只对5/24。强制实际网格会改变长按和模板，部分二指fixture头数46→43；没有为了网格指标修改生产gate。

## 后续比较与复现

历史V8入口 `benchmark-signal.mjs` 保持原样，需检出对应源码复现其冻结结果。新 `benchmark-dsp.mjs` 提供 `prepare → freeze → run`；输入仍为固定十类×三编号的30段、22050Hz单声道f32le。先用 `--help` 查看选项，运行 `npm run test:benchmark` 验证11项状态/指标及合成SSR流程。

新入口将 source closure、package-lock、评价器、Node版本、物理参考边界、指标和gate绑定到协议。`diagnostic`可重复运行observed数据，永远不形成新未见声明；`final`逐文件ID和PCM查持久[观察登记](dsp-cohorts.json)，在首次算法加载前consume整组，失败也不恢复fresh。登记现含150段；fixture的假文件名不是实际曲目评价。

复现本报告应重新prepare为diagnostic，使用版本8完整commit作baseline、当前版本9作candidate、相同6/18/33输入及门槛。可复制登记到本地忽略目录并显式指定 `--registry`，保留项目公开历史。持久登记是可信项目记录，不能防御人为删除或替换历史；最终数据独立性也只限文件名/精确PCM，不证明作品、演奏者或训练数据独立。
