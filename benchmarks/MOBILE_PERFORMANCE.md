# 手机加载与运行稳定性验证

2026-10-30。源码仍是静态浏览器应用；本轮处理主线程合成、增强结果重复复制、菜单绘制和首屏脚本负担。模型与编谱仍为版本 7，判定规则为版本 2。

[测量摘要](mobile-startup-2026-10-30.json) 只包含统计、产物哈希和检查结果，没有用户音频或谱面数据。

## 首屏对照

基线为已发布的 `e122c16` 静态产物，包含其实际动态依赖；候选为本轮最终构建。分别启动独立 Edge、844×390 移动视口、DPR 2、触控配置、CDP 6 倍 CPU 节流，用原版内置演示曲走真实增强 ONNX/WASM。资源由本地静态服务器提供，要求最终识别来源确实为增强；模型失败回轻量的运行不计入此对照。以下为单次有效基线和最终候选运行，不是多次统计或真实手机速度承诺。

| 测量项 | 原版 | 本轮 |
| --- | ---: | ---: |
| 主入口 JS，原始字节 | 444,439 | 397,498 |
| 主入口 JS，gzip 字节 | 143,631 | 129,336 |
| 首次预览 Canvas 绘制 | 3.248 s | 1.404 s |
| 就绪前最长主线程任务 | 2.772 s | 1.026 s |
| 增强演示曲谱面就绪 | 10.053 s | 8.647 s |

主入口压缩体积减少约 9.95%；新增独立 Demo Worker 约 1.86 kB 原始代码。使用 `motion/react-m` 与静态 `domAnimation`，没有为动画引入额外异步等待点，三处进入动画与结果 spring 继续使用原参数。

Canvas 指标表示预览首帧，不能当成整页首次内容绘制。桌面节流不等于真实 Android/iPhone。首次增强识别的模型和 WASM 仍约 24.3 MB 未压缩资源；本地网络对照不包含实际移动网络下载耗时。

## 菜单预览绘制

同一次桌面 headless 环境，每个状态采样 1.2 秒。该机器原版 RAF 约 240 Hz，这不是手机刷新率结论。

| 状态 | 原版绘制次数 | 本轮绘制次数 |
| --- | ---: | ---: |
| 可见 | 290 | 36 |
| 移到视口外 | 289 | 0 |
| 回到视口 | 282 | 35 |
| 系统减少动画 | 289 | 0 |
| 页面隐藏事件 | 289 | 0 |
| 回到前台 | 288 | 35 |

菜单最高 30 FPS，并在 busy/compiling/help/result/starting 时停止 RAF。暂停原因解除后继续预览时间，不把离屏时间算入。只在数据、速度、下落方式变更时重建；同尺寸 ResizeObserver 回调不重复绘制。操作指南和结果遮罩的额外浏览器检查也观察到 0 次绘制，关闭后恢复。游戏继续使用原音频时间线与触控判定。

## 音频准备与数据传输

- 原创演示曲由 Worker 合成，主线程只创建 AudioBuffer 并接收一次 transferable PCM 拷贝。44.1 kHz、2,066,085 个样本；纯函数、同步旧接口和 Worker 路径在同一运行时都与冻结旧实现逐字节相同。Windows/Node24 的历史 PCM 哈希为 `36a3f9421d456dfa9829efa25223785da2d90963699d2352522a30d791cf5aaf`，不作为跨运行时固定值。取消、构造/消息/线程错误及 30 秒总超时都会清理，失败不在主线程重算。
- 实际《九万字》使用发货模型完成增强，捕获到一次完整 baseline、一次 patch、零次完整 done。在 App 向编谱 Worker 发送前，六组频谱/能量/起音数组与收到的 baseline 保持同一引用。该次基础快照 JSON 为 2,459,044 字符，新增 patch 为 89,009 字符；此前同曲完整增强结果 JSON 为 2,496,876 字符。这只是序列化负载例子，不是总 RAM 测量。
- 单/二/三/四指分别 366/461/661/783 个音符，所有音符及完整谱面 JSON 都与本地旧参考逐一相同。原参考未覆盖、未公开分发。
- 新上下文阻断模型资源后，轻量 fallback patch 只有 recognition，共 112 个 JSON 字符；六组数组及 rhythm/pulse 都复用 baseline，结果与轻量谱面相同，开始按钮可用。音乐和分析未上传。

## 兼容与故障恢复

浏览器故障注入覆盖演示 Worker 挂起取消、构造失败、专属超时后的导入恢复，以及系统减少动画、指南和结算遮罩。原生 Web Audio 六秒测试曲完整自动演示并结算，不写最佳成绩。

在完整 legacy MediaQueryList 注入中曾发现 Motion 依赖无条件调用 addEventListener。现于首次 React render 前仅对独立的 reduced-motion 查询安装 legacy change 事件桥接；现代 API 保持原函数身份，其他媒体查询不改。桥接的 listener 去重、移除、this、capture、once 与 signal 均有单测。保留旧失败记录后，原完整 legacy 注入的 7 项场景重新全部通过，实际 addListener/removeListener 均被调用，无页面异常。它不是通用媒体查询 polyfill，也不能证明真实旧 Safari 的所有能力。

常规测试共 325 项通过，1 项私有歌曲测试默认跳过；生产构建通过。现代 API 控制场景和原落点音浏览器检查也通过。

全曲等价测试使用 `test-fixtures/demo-e122c16.ts` 中冻结的原函数，独立于新合成器，逐字节比较完整 PCM，不使用多平台哈希允许列表或近似采样。初次 Linux/Node22 CI 的固定本机哈希断言和大数组身份 matcher 超时曾阻止部署；修正后使用同运行时旧新比较，生命周期身份验证为布尔引用检查加原生全缓冲比较，只有真正完整合成对照使用较长测试预算。修正后的跨环境结果以对应提交的 Actions 为准。

真机的内存峰值、热降频、续航、系统音频中断和触控舒适度仍需实际设备确认。没有把节流测试、JSON 大小或自动演示满分当成这些结果。
